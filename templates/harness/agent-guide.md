# agent 起草向导：如何沉淀第一条 REQ/TC

> 本文件是给 AI 编码代理的操作协议（init 落盘于真源目录）。人类读者可当风格指南看。
> 核心原则：**考古先于起草、人审先于入库、存量封顶增量防护。**

## 五步起草协议

### 1. 考古：先看现状，别凭理想写
- 对目标路径先跑统计：该模式在存量代码里出现几次？`grep -rn "<模式>" src/<路径> | wc -l`
- 存量已有 N 处违背 ≠ 条款作废：写成「存量封顶（现有 N 处登记豁免），增量不得新增」。

### 2. 面试：一次只问一个问题（不批量）
逐条向用户确认三件事：
- 这条模式当初解决什么问题？
- 有没有合法的例外场景？
- agent 最容易在这里犯什么错？

### 3. 起草 REQ（「不得」句式，一条一个义务）
```markdown
REQ-001 | <标签> | TC-001 | <一句话标题（含否定语义）>
REQ-001: <澄清正文：真源字段名/守卫 token/边界与违反后果，含「不得…」>
```

**白话文纪律（人审可读性，强制）**：澄清正文（以及 inbox 草稿卡、人审提示）写给「没参与过本模块的同事」看——先讲场景（谁、在做什么操作时），再讲禁止行为，最后讲违反后果；术语/代号首次出现给一句话解释，禁止堆内部缩写。自检：读给一位未参与的开发，能一句话复述「这条不许我干什么」才算过。
- 反例（术语先行，人审看不懂）：「展示值必须由 A/B 字段还原（存量封顶 N 处），增量不得引用」；
- 正例（白话）：「列表页的联系方式只能用后端的网页地址、邮箱两个字段拼出来；不要再读旧的合并字段，否则邮箱会整列消失。旧代码里已有 3 处，新代码不许再加。」

### 4. 起草 TC（G/W/E/V，V 优先 grep 计数式命令）
```markdown
TC-001: G=<前提> | W=<改动动作> | E=<预期> | V=`grep -c "<守卫token>" src/<文件>`
```
V 字段写反引号包裹的命令即可执行；**不得写破坏性命令**（rm 递归/sudo/下载管道进 shell——verify 侧有确定性拒绝兜底）。

### 5. 自验：召回可达 + 结构合规
- 模块 `index.md` 登记命中路径与标签：`` - `src/<路径>/` [strong] | <标签> ``
- 跑 `reqbank scope "<任务>"` 确认能召回；跑 `reqbank check` 过 tag-coverage。
- 没有「## 断言」的条款不算存款、不会硬拦。守卫写成：`REQ-001 | no-delete | <守卫token>`。
- 误报出口：diff 里写 `reqbank-ignore: <scope:id>`，或索引第 5 列加 `:warn`——写前/critic/Stop/gate 都认，且必须可见可数。

## 自动化行为（0.18.0 起）

- **沉淀提醒按文件去重**：critic 对「零覆盖业务编辑」的 `[reqbank 自动沉淀]` 提示，从每回合一次改为每文件一次——同一回合改 N 个未覆盖文件就有 N 次提示；重复编辑同一文件不重复打扰。
- **模块候选自动起草**：Stop 钩子把本回合「零覆盖」的真实改动按目录聚合成模块草稿（`inbox/module-drafts/<slug>.md`，含累计证据文件、建议命中路径 `[strong]`、激活步骤），跨回合增量累积。agent 在回合内应优先直接按五步协议初始化模块；草稿只是兜底证据链。激活仍须人审：按草稿内四步操作后删除草稿。
- 边界不变：引擎永不直接写 `modules/`；草稿激活前不参与召回，任何钩子都不会匹配它。

## 禁止事项
- 不得跳过人审直接写 modules/（`mine` 的候选一律先落 inbox/）。
- 不得起草无法验证的条款（没有可执行 V 的 TC 是债务不是资产）。
- 不得让澄清正文塞多个义务——拆条。
